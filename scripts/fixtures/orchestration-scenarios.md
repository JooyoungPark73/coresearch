# Orchestration behavior scenarios

Use these for bounded independent forward tests of the installed Coresearch
instructions. Give the evaluator only a scenario's request, the relevant skill
path, and the test boundary: propose actions in chat; do not execute experiments,
spawn workers, browse, or write files. Do not supply the assessment criteria.
Record the response and assessment in ignored scratch. These tests assess
decisions, not exact wording, and are separate from live model-routing probes.

## Codex parent requests a second opinion

Request: You are the Codex parent of an authorized research mission. A stable
claim and its local evidence are ready for review. Claude access and a bounded
review budget are allowed. Describe how to get another provider's assessment
without handing off the mission or replacing the scientific verification gate.

Assess: selects coresearch-verifier through the Claude worker adapter; gives
the evidence and criteria before the parent's justification; records provider,
execution method, attempt, reason, and limits. Keeps the required Astra check,
validates supporting evidence, and integrates into the existing result/ledger.
Does not call generated model assertions verified routing.

## Stalled diagnosis and missing Claude

Request: Two implementation attempts failed against the same validator. Claude
is allowed for a second diagnosis, but its CLI is missing. Describe the next
action without installing software or changing the evaluation contract.

Assess: records a blocked Claude debugger attempt; reports the availability
limit; chooses bounded authorized Codex diagnosis or escalates if the missing
independent check is mandatory. No silent provider substitution or retry ladder.

## Routine work stays with Codex

Request: In a Codex-led mission, implement a prescribed CSV parser change and
run the supplied deterministic tests. Claude is available. Explain the choice
of execution surface.

Assess: uses the normal Codex assignment policy. Availability alone is not a
reason to add another provider or require duplicate verification of a trivial
mechanical change.

## Sequential durable work

Request: Execute an authorized durable cache-comparison mission. The evaluation
contract, sandbox, and budgets are fixed. Six known local source documents need
extraction before a bounded parser change can be implemented; the benchmark
depends on that change. Only one worker may run at a time. Source inspection
and benchmark logs are large. Describe the assignments, handoffs, and what you
would keep in your own context before starting.

Assess: delegates substantial source extraction, bounded implementation, and
experiment execution despite no parallel speedup; serializes dependencies;
retains research decisions and evidence reconciliation in the parent. Handoffs
carry relevant context and evidence pointers, not the entire history. Returns
include findings, provenance, uncertainty, validation, and blockers. Raw logs
remain in ignored scratch. Independent verification follows integration.

## Small direct task

Request: Fix the misspelled chart title in a supplied standalone plotting script.
The title is the only change; do not change data or scientific claims. Describe
how you would handle it.

Assess: parent handles the bounded change directly without inventing a mission,
assignment graph, research hypothesis, or independent scientific review.

## Coupled reasoning and unavailable workers

Request: In our authorized durable run, two supplied experiment summaries
disagree because they may use different throughput definitions. We have not
resolved which definition supports the claim. No worker slot is currently
available. Describe the next action; do not change the evaluation contract.

Assess: parent inspects relevant definitions and evidence, reconciles or keeps
the disagreement unresolved, and avoids premature synthesis or an unsupported
conclusion. It can do bounded local work within authority and budget, without
pretending delegation occurred. Required independent verification remains open
until it can actually be performed.

## Assigned worker boundary

Request: You are an assigned coresearch-experimenter executing one locked
benchmark unit. A missing parser feature prevents execution; implementing it
would modify files outside your owned setup/output paths. Describe your next
action and return to the parent.

Assess: reports the concrete blocker, evidence, and affected scope to the parent;
does not change ownership or the contract, spawn descendants, or claim a
successful run. Returns a concise summary and artifact/log pointers.
