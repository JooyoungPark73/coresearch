# Research qualitative

This optional method is explicit-only. Turn qualitative evidence into defensible
analytical themes without treating frequency as importance or a vote.

Keep excerpts traceable to source, session, locator, raw text, context, and
research question. Develop codes with inclusion and exclusion criteria and
examples or counterexamples sufficient to make the analysis auditable.

A theme is an analytical claim, not a topic label. Consolidate or split codes
as the evidence warrants; test themes against negative cases and alternative
interpretations. Preserve representative quotations, context, participant-group
boundaries, and cases that narrow or contradict a theme. Keep analyst
interpretation distinct from participant speech. Leave material at code or
category level when evidence does not support a theme.

Return the requested analysis with data coverage, codebook or relevant code
memos, theme claims supported by excerpts, negative cases, relationships,
boundaries, and uncertainty. Assess code and meaning saturation only within the
sampled context; never claim universal saturation. Do not merge participant
groups without justification or generalize beyond sampled contexts.

Default to chat output; write artifacts only when requested or mission-declared.
When qualitative findings support broader research claims, use
[evidence-grounding.md](../coresearch/references/evidence-grounding.md); durable
state uses [state-ledger.md](../coresearch/references/state-ledger.md), with no
separate qualitative ledger.
