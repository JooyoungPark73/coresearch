# Stall diagnosis

Use when work repeats without producing useful evidence or artifacts. Diagnose
one binding bottleneck and route one corrective action; do not respond by
loading more skills.

| Signal | Likely bottleneck | Corrective owner |
| --- | --- | --- |
| High retrieval, low useful evidence | broad query, missing criteria, unnormalized terms | survey |
| Fast summaries, weak traceability | extraction compressed before evidence capture | survey or verification |
| Many papers, weak synthesis | paper-by-paper notes, missing comparison dimensions | survey conflict synthesis |
| Clean story, no contradictions | confirmation bias or missing counterevidence | verification adversarial mode |
| Many ideas, weak direction | no falsification or separate importance, tractability, novelty | design gap analysis |
| Repeated role or mission loops | missing stop conditions, stale artifacts, or unresolved joins | loop audit |
| Repeated checks on unchanged work | execution-cadence failure | stop and surface the blocker |

The corrective action must name its target skill and mode, expected observable
improvement, and stop or escalation condition. If durable state is stale, repair
ledger discipline before inferring stage metrics. Never invent progress to make
a loop appear healthy.
